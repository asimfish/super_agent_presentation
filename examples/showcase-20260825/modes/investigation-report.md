# 推理 p99 延迟调查

## 结论

在给定合成重放条件内，250 ms 的 batch flush timer 是延迟上升的已支持根因：它可复现 910 ms p99，而仅将 timer 改为 25 ms 后，p99 降至 515 ms；其他控制保持不变。调查是只读的，没有实施生产修复。

本报告仅使用合成展示数据，不代表真实研究或生产结果。

## 症状与范围

症状是 p99 从 480 ms 升至 920 ms。调查固定请求语料、并发 8、模型构建和主机，只覆盖一次受控重放；原始观察见[合成证据包](../inputs/investigation-report.md)。

## 已证实发现与假设比较表

- 队列等待从 35 ms 增至 310 ms，而 CPU 变化不超过 2 个百分点。
- 250 ms timer 的受控探针得到 910 ms p99。
- 25 ms 反事实探针得到 515 ms p99。
- 关闭响应压缩只改变不到 5 ms，不能解释约 440 ms 的主要差异。

下表说明每个候选解释被支持、排除或保留为未决的依据。

| 假设 | 状态 | 区分证据 |
|---|---|---|
| flush timer 过长 | 支持为当前根因 | 单变量重现与反事实恢复 |
| 响应压缩 | 在本次范围内排除为主要原因 | 差异小于 5 ms |
| CPU 饱和 | 不支持 | CPU 基本稳定 |
| 跨主机或长期内存因素 | 未决 | 未测试第二主机或长时间运行 |

## 边界与下一步

该因果结论仅适用于合成重放和当前主机；真实流量、另一主机及长期运行尚未验证。下一步是在不改其他变量的前提下，于第二主机重复两个 timer 水平，再决定是否修复生产配置。
