# SYN-API-DOC v0.2 审查

## Findings

### F1｜高严重级别｜重试可能产生重复写入

- **定位：** section 2, line 14。
- **证据：** 文档允许超时后重试，但在已审 section 2–4 中没有 idempotency key 或 duplicate-write 语义。
- **影响：** 客户端无法判断重试是安全重复还是第二次写入，可能破坏写入唯一性契约。
- **建议：** 明确幂等键、服务端去重窗口和重复请求响应；若 API 本就非幂等，应显式禁止自动重试。

### F2｜中严重级别｜缺失值与测量零不可区分

- **定位：** section 3, line 26。
- **证据：** omitted count 与 measured zero 都编码为数值 `0`。
- **影响：** 消费者会把“未观测”当作真实零，导致聚合和告警语义错误。
- **建议：** 使用 nullable 字段或伴随 `observed` 状态，并在 schema 中定义两种语义。

本报告仅使用合成展示数据，不代表真实研究或生产结果。

## 范围、边界、正向证据与后续行动

审查对象仅为[合成文档证据](../inputs/review-report.md)中的 section 2–4，标准是重试语义与零/缺失区分。section 4, line 41 明确定义了 `AUTH_DENIED` typed error，这一契约应保留。

当前判定为**需要修订**：F1 会影响写入正确性，F2 会影响数据解释。未审实现、测试、部署配置及其他章节，因此不能声称 API 实际可被重复写入，也不能声称文档不存在其他问题。
